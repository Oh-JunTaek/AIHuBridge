# 일일 갱신·자료 누적 보관 구현 결과

> 2026-10-28 작업 결과다. 현재 정책은 [자료 수명 기준](../standards/CONTENT_LIFECYCLE.md), 상태는 [PLAN](../../PLAN.md)을 따른다. 이번 변경은 로컬 검증·커밋까지이며 원격 cron·운영 배포 검증과 구분한다.

## 사용자 선택

- 일반 뉴스·업계·정책·개발 도구 30일, 모델 소식 90일, 논문 180일. 달력 개월이 아닌 일수 기준이며 자료 성격 우선(논문 → 모델 → 일반)을 적용한다.
- 최신 7일 기본 탐색과 이전 자료의 기간별 검색. 수집은 매일 한국시간 오전 7시 1회.
- 마감 후 개최 전 행사는 유지하고 신청 마감 표시. 종료 행사·개최일 미확인 마감 공고는 지난 자료로 30일 보관한다.
- 취소·연기는 기본 달력에도 상태를 표시해 유지하고 원문 새 날짜를 반영한다.

## 변경

- 공통 content-retention 모듈에서 소식 30·90·180일, 기본 7일, 일정 이력 30일을 관리한다. 원문 게시일로 만료하며 수집일로 연장하지 않는다.
- 소식은 정상·부분 실패 모두 기존 자료를 기간 안에서 합쳐 보관한다. 같은 URL은 최신 내용을 우선하며 회당 수집 한도와 누적 보관량을 구분했다. 수집 전체 실패는 원래 파일을 유지한다.
- 기존 source별 신규 한도는 유지했다. 실수집 시험에서 arXiv 피드에 약 1천 항목이 있었으므로 전체 피드 무제한 편입을 새 정책으로 추가하지 않았다. 논문 회당 24건·분야별 선택 및 기존 8/12/16건 한도에 누적 보관을 결합한다.
- AI 소식에 최근 7/30/90/180일·보관 전체 기간 필터, 홈 최근 7일, 조건 초기화, 만료 자료 브라우저 제외를 적용했다. 탐색·선호 기록을 저장하지 않는다.
- 행사 수집·상태·표시·보관을 분리했다. 마감된 개최 전 일정과 종료 행사·지난 공고를 구분하고 기본/과거 포함·신청/취소/연기 상태 필터를 달력·목록에 함께 적용한다.
- 시간대 미확인 날짜는 마지막 현지 날짜의 UTC-12 하루 끝을 보관 전환 경계로 사용한다. 실제 종료 시각 필드를 만들지 않고 카드에 미확인을 표시한다.
- 명시적인 취소·연기 제목 공지와 같은 제공처 ID/URL의 기존 일정을 연결한다. 새 날짜 미확인 시 기존 날짜를 ‘변경 전 참고’로 명시하고 최초 관찰 시각을 반복 갱신하지 않는다. 취소 부정 표현·일반 정책 제목의 오인을 방지했다.
- .github/workflows/refresh.yml의 cron만 `0 22 * * *`로 바꾸었다. News Refresh 이름·권한·검증·workflow_run 연결·JSON 4종은 유지했다.
- PLAN·README·AUTOMATION·SOURCE_REGISTRY를 새 정본에 연결했다. 이전 보고서는 당시 이력으로 유지한다.

## 검증과 운영 경계

회귀 검사 **87건**, 타입·selfcheck·빌드 통과. YAML 파서로 구문·일일 cron·workflow_run 연결을 확인했다. 기존 Tailwind sourcemap 경고는 남지만 빌드는 성공했다. 새 설정의 원격 실행 검증은 아직 수행하지 않았다.

기존 73건 검사 중 새 정책과 충돌하는 마감 즉시 제거·7일 실패 보존·시작일 즉시 제외 기대값을 사용자 결정에 맞춰 변경하고 만료·누적·중복·실패·과거 자료·상태 갱신 검사를 추가했다.

시행 전 삭제 자료나 RSS가 제공하지 않는 과거 자료는 완전 복원하지 않는다. 취소·연기 표현이 없거나 출처 갱신이 늦으면 자동 탐지가 누락될 수 있다. Git 이력 삭제나 외부 본문 재게시를 수행하지 않는다. 저장 JSON은 수집 시 정리하고 화면은 시각 기준으로 만료를 제외한다.

원격 스케줄·봇 저장·후속 배포는 이번 변경에 대한 승인 후 실제 확인해야 한다. 기존 배포 복구의 성공 실행을 새 설정의 원격 검증으로 재사용하지 않는다.
