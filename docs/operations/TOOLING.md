# 도구 운영 기준 — 스킬·MCP·Cline 플러그인

기준일: 2026-10-28. 사용자 결정에 따라 충돌하는 예전 저장소 사본은 비활성 보관했다. 이 문서는 실제 활성화·설치 성공을 보장하는 등록 매니페스트가 아니다.

## 도구 종류와 경계

| 종류 | 역할 | 확인 사항 |
|---|---|---|
| 스킬 | SKILL.md 기반 작업 지침 | 호스트의 실제 탐색 경로·발견 여부 |
| MCP 서버 | 도구 호출 제공 | 서버 시작·목록·입출력·최소 권한 |
| Cline SDK 플러그인 | SDK 확장 코드 | 지원 버전·실제 매니페스트·로드 성공·작업 루트 |

SKILL.md의 존재만으로 Cline 플러그인이 정상 등록됐다고 판단하지 않는다. `.agents/skills`와 `.cline/plugins`의 복사본을 동시에 활성 설치로 안내하지 않는다.

- 새 프로젝트 플러그인은 프로젝트 `.agents` 아래에 두며 사용자 요청 없이 원격으로 보내지 않는다.
- 스킬 탐색 경로는 호스트가 제공한 실제 목록으로 확인한다. 사용자 홈 `C:/Users/wns53/.agents/skills/`와 프로젝트 사본은 서로 다르며 저장소 사본 격리가 홈 사본을 변경하지 않는다.
- 플러그인을 다시 개발할 경우 작업 루트는 `ctx.workspaceInfo?.rootPath` 등 지원 API로 확인하고 저장소 밖 접근을 차단한다. 필요한 capability만 선언한다.
- 플러그인의 새 의존성은 검증한 Node builtins 또는 @cline/*만 사용한다. 이 제한을 기존 웹 앱 의존성 전체 삭제 지시로 해석하지 않는다.
- 새 외부 계정·키·유료 서비스는 사용자 확인이 필요하다. 현재 서비스에는 OpenRouter·로컬 모델·행사 생성 기능을 넣지 않는다.
- SKILL 안내, MCP 설정, SDK API는 서로 대체 규격이 아니다. 새 도구가 필요할 때 실제 호스트 지원 규격을 검증한 후 별도 작업으로 개발한다.

## 현재 저장소 상태

| 과거 사본 | 처리 | 로컬 보관 위치 |
|---|---|---|
| .agents/skills/aihubridge-tools | 자동 발견 경로에서 제거 | .agents/disabled/aihubridge-tools-skill |
| .cline/plugins/aihubridge-tools | 예전 로더 경로에서 제거 | .agents/disabled/aihubridge-tools-cline |

두 사본은 원문 내용을 유지하고 SKILL.md·index.ts·package.json을 각각 .disabled 이름으로 변경했다. 보관 폴더는 Git 무시 대상이며 새 커밋·push에 포함하지 않는다. 이전 Git 이력의 사본을 삭제하는 것은 아니다.

예전 안내는 삭제된 OpenRouter 모듈·API 키·뉴스 기반 가상 행사 생성·검증 완화 옵션을 포함하며 현행 계약과 충돌한다. 위 사본을 실행하거나 과거 문서의 설치 명령을 사용하지 않는다. 현재는 아래 검증된 저장소 명령만 사용한다.

## 현재 사용 명령

프로젝트 루트에서 실행한다.

~~~sh
npm run refresh     # 실제 RSS·공개 일정 수집
npm run selfcheck   # 데이터·일정 근거·참조 무결성 검사
npm test            # 수집·분류·날짜·실패 처리 회귀 검사
npm run lint        # TypeScript 검사
npm run build       # 제품 빌드
~~~

스킬에 쓰인 --force·--limit·--strict 옵션이 위 스크립트에서 지원된다고 추정하지 않는다. 원격 수동 수집은 AUTOMATION의 승인 규칙을 따른다.

## 미검증 경계와 과거 장애

2026-10-27 자료에 Cline 플러그인 $schema 로딩 오류·장기 세션 Provider 오류가 기록되어 있다. 이번 정리는 저장소 사본을 격리했으며 Cline 자체·외부 홈 스킬·MCP 설정·세션 재현 테스트를 실행한 것은 아니다. 따라서 ‘현재도 API 장애가 확정’ 또는 ‘Cline 정상화 완료’라고 표시하지 않는다.

외부 설정의 경로 참조를 변경하거나 새 플러그인을 만들 필요가 생기면 작업 범위를 먼저 확인한다. 로드·도구 목록·작업 루트 경계·최소 입출력·회귀 검사를 통과하기 전 활성화하지 않는다.
