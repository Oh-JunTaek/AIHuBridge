# 문서 우선순위와 이력 관리 기준

기준일: 2026-10-28. 서로 다른 시점의 문서·구현·사용자 결정을 혼동하지 않기 위한 기준이다.

## 무엇을 기준으로 삼는가

1. **현재 세션의 사용자 결정**을 먼저 따른다. 문서의 ‘사용자 확정’ 표현만으로 현재 사용자 지시를 덮어쓰지 않는다.
2. **AGENTS.md**는 작업 경계·승인·공통 개발 규칙이다. 개별 기능 수치와 작업 이력을 누적하지 않는다.
3. **PLAN.md**는 제품 범위·현재 구현 여부·남은 작업의 유일한 관리 인덱스다.
4. 세부 계약은 **operations/AUTOMATION**, **operations/TOOLING**, **standards/SOURCE_REGISTRY**, **standards/TERMINOLOGY**가 각각 한 곳에서 관리한다. README는 외부 소개, docs/README는 문서 지도다.
5. **실제 코드·테스트·Git·Actions·공개 JSON**은 현재 구현·운영 상태의 증거다. 코드가 문서와 다르면 정책을 코드에 맞춰 몰래 바꾸지 말고, 사용자 의도가 명확할 때 구현을 고친다.
6. **docs/archive**는 당시 상태를 설명하는 기록이다. 그 안의 ‘현재’, ‘다음 작업’, ‘완료’, ‘최신’, ‘정책’은 작성 당시 기준이며 현행 지시가 아니다.
7. **docs/archive/originals**는 원본 보존용이다. 오래된 링크·잘못된 주장도 원문 일부이므로 수정하지 않는다. 검색 결과에 나왔다는 이유로 실행하지 않는다.

서로 다른 최신 사용자 결정이 확인되지 않으면 해당 항목을 질문하고, 답이 필요한 작업만 보류한다. ‘문서가 더 최근이니 무조건 맞다’ 또는 ‘코드가 이미 있으니 승인됐다’고 판단하지 않는다.

## 상태 표현

- **확정 범위**: 사용자가 정한 요구사항. 구현 완료와 다르다.
- **구현됨**: 실제 코드가 존재하고 확인한 상태. 운영 배포·실기기 검증과 다르다.
- **검증됨**: 날짜·커밋·검사 또는 실행 ID와 범위를 함께 적는다. 호스트 검사·브라우저·실기기·스크린리더를 구분한다.
- **계획만**: 설계·검토 대상으로 남겨 둔 항목. 메뉴나 수집기가 있다고 추정하지 않는다.
- **제외/삭제됨**: 이번 버전에 넣지 않는 기능. 미완료 기능 체크리스트로 다시 올리지 않는다.
- **미확인**: 근거가 없거나 현재 상태를 재현하지 못한 항목. 실패 확정·무료·활성화·안전·완료로 바꾸지 않는다.

데이터 건수·테스트 수·Git clean 여부·배포 상태는 고정 사양이 아니다. 보고서에 기준일과 근거를 붙이고 이전 보고서 수치를 현재 값으로 복제하지 않는다. 출처 정책 검토일은 코드 대조일이나 문서 이동일로 갱신하지 않는다.

## 이력 보존·이동

- 현행 규칙은 정본에서 갱신한다. 날짜별 결과 보고서는 archive에 두고 PLAN에서 근거 링크만 연결한다.
- 열람용 이력은 맨 위에 역사적 기록임을 표시하고 파일 이동에 따른 상대 링크만 고친다. 본문을 현재 결론에 맞춰 덮어쓰지 않는다.
- originals는 원문 그대로 보존한다. 원본과 열람용 사본의 역할을 archive/README에서 설명한다.
- 문서 이동 시 루트의 옛 복사본은 남기지 않아 중복 정본을 만들지 않는다. Git 이력·보관 사본으로 복구할 수 있어야 한다.
- 활성 문서의 상대 링크와 보관 사본의 링크를 검사한다. originals의 옛 링크는 검사에서 제외한다.
- 일반 `rg` 검색으로 운영 상태를 파악할 때 archive·originals·비활성 도구를 제외하고, 이력 조사 때만 포함한다.

## 승인과 배포

문서에 적힌 자동 배포 동작과 에이전트의 원격 실행 허가는 별개다. master push가 자동 배포를 일으키더라도 push 자체의 승인 범위를 먼저 확인한다. 과거의 특정 복구 작업 승인을 이후 문서 정리 작업의 원격 전송 허가로 확대하지 않는다.

이번 충돌 정리 작업은 로컬 검증·커밋까지 진행한다. 원격 push·배포는 이번 변경에 대한 명시 승인 후 진행한다.
