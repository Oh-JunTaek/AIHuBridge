# 자료 갱신·보관·노출 기준

기준일: 2026-10-28. 사용자가 순차 선택한 정책의 정본이다. 기존 ‘하루 2회·최신 자료 교체·실패 시 7일 보존·신청 마감 즉시 제외’ 규칙보다 이 문서를 우선한다. 원격 반영 여부는 PLAN의 작업 결과를 확인한다.

## 갱신

- GitHub Actions에서 **매일 한국시간 오전 7시 1회** 수집한다. UTC cron은 `0 22 * * *`다. 실행 대기열 지연은 가능하다.
- 뉴스·공식 발표·논문은 기존 RSS/공식 Atom, 행사는 기존 공개 출처를 사용한다. 새 계정·키·LLM·개인 PC 상시 실행은 필요 없다.
- 수집 → 검사 → 봇 JSON 4종 커밋 → 성공한 News Refresh의 workflow_run 배포 연결을 유지한다. 실패·취소 시 후속 배포하지 않는다.
- 웹사이트는 정적 JSON을 읽는다. 방문 때 수집 작업을 실행하지 않는다. 정적 교육·인증 조건은 별도 검토 대상이다.

## AI 소식 보관과 탐색

| 자료 성격 | 보관 기간 | 기준 |
|---|---|---|
| 일반 뉴스·업계·정책·개발 도구 소식 | 30일 | 원문 게시일 |
| 모델 소식 | 90일 | 원문 게시일 |
| 연구 논문 | 180일 | 원문 게시일 |

- ‘개월’은 일수로 계산한다. 1개월=30일, 3개월=90일, 6개월=180일이다. 경계 시각에 도달하면 사이트 보관·검색 대상에서 제외한다.
- 성격이 겹치면 **논문 → 그 외 모델 소식 → 일반 소식** 순으로 적용한다. 논문 출처·연구/논문 분류·원문 분야 코드, 기존 모델 키워드 분류를 사용한다. LLM 판정이나 중요도 평가가 아니다.
- 기본 화면과 홈은 **최근 7일**이다. AI 소식의 게시 기간에서 7·30·90·180일 또는 보관 중인 전체 기간을 선택하고 기존 검색·분야·지역·언어·제공처 조건과 조합한다. 조건 초기화는 최근 7일로 돌아간다.
- 정기 수집 성공 시 새 자료와 기존 자료를 URL 기준으로 합친다. 새로 확인한 동일 URL 내용을 우선하고 중복·기간 만료 자료를 정리한다. RSS에서 사라져도 기한 안에서는 유지한다.
- 회당 새 수집 한도는 news-sources.mjs의 기존 값(기본 8·모델/플랫폼 16·신규 국내 12·논문 24)을 유지한다. **누적 보관 총량에는 회당 한도를 적용하지 않는다.** 논문은 원문 분야별로 나눠 선택하며 획기성 순위로 표현하지 않는다.
- 출처 일부 실패 시도 같은 30·90·180일 보관 규칙을 적용하고 부분 실패 경고를 남긴다. 전체 실패는 파일을 바꾸지 않는다. 정상 빈 RSS와 네트워크·구조 오류를 구분한다. 유효한 새 자료와 보관 자료가 모두 0건이면 파일 교체를 막는다.
- 재수집일이나 성공 실행 시각으로 원문 게시일·보관 기간을 갱신하지 않는다. 브라우저도 만료 기준을 적용하므로 수집 장애 때 오래된 파일이 남아도 만료 자료를 검색 결과로 보여주지 않는다.
- 시행 전에 이미 버린 자료나 RSS가 제공하지 않는 과거 자료는 복원하지 않는다. 180일을 보관한다고 처음부터 180일치가 존재하는 것은 아니다. 모든 발행 자료를 빠짐없이 수집한다는 보장은 없다.

## 캘린더

| 상황 | 기본 달력·목록 | 보관 |
|---|---|---|
| 신청 마감 전, 개최 전 | 유지 | 일정 기준으로 유지 |
| 신청 마감 후, 개최 전 | 유지, 신청 마감 표시 | 개최 일정까지 유지 |
| 종료된 행사 | 기본 숨김, 지난 행사·공고 포함으로 조회 | 종료 기준 이후 30일 |
| 신청 마감만 있고 개최일 미확인 | 기본 숨김, 지난 공고로 조회 | 신청 마감 이후 30일 |
| 원문 취소·연기 확인 | 기본 달력에도 상태 표시 | 기존 일정 종료 기준 또는 최초 공지 관찰 시각 중 늦은 기준 이후 30일 |

- ‘지난 행사·공고 포함’을 켜면 보관 중인 과거 자료도 달력·목록·검색에 반영한다. 조회 월이나 전체 기간으로 이전 자료를 찾는다. 기본 국내·온라인 범위와 다른 필터도 함께 적용된다.
- 신청·행사 상태에서 신청 마감 전(마감일 확인), 마감, 취소, 연기, 마감일 확인/미확인을 구분한다. 취소·연기·미확인·신청 예정·지난 행사를 ‘신청 마감 전’에 포함하지 않는다. 실제 잔여 좌석·참가 자격을 보증하지 않는다.
- 종료 시각이 명시되면 그 시각을 기준으로 한다. 날짜만 있으면 마지막 현지 날짜를 기준으로 하되 시간대 미확인의 경우 UTC-12 하루 끝까지 보수적으로 유지한다. 시작 시각만 있으면 해당 한국시간 날짜 끝을 표시 전환 기준으로 사용한다. **이 계산은 보관·표시 경계이며 실제 종료 시각 필드를 생성하지 않는다.**
- 따라서 정확한 종료 시각이 없으면 ‘지난 행사 · 종료 시각 미확인’으로 안내한다. 개최일이 없는 공고는 ‘행사 종료’라고 표시하지 않는다.
- 취소·연기는 원문의 명시적인 제목 공지로 확인한다. 목록에서 사라졌다는 이유만으로 취소를 추정하지 않는다. 부정 표현·일반 취소 정책 제목은 공지로 처리하지 않는다. 출처의 갱신 지연·표현 차이에 따른 누락이 가능하므로 원문 확인을 안내한다.
- 새 날짜가 확인되면 반영한다. 기존 자료에 대한 연기·취소 공지에 새 날짜가 없으면 기존 날짜는 **변경 전 참고 일정**으로 유지한다. 이 경우 최초 공지 관찰 시각부터 30일 보관하며 재수집으로 연장하지 않는다. 처음 보는 날짜 미정 자료에 가짜 날짜를 만들지 않는다.
- 정상 목록에서 사라지거나 일부 출처가 실패해도 기존 유효 자료는 위 기간 안에서 보존한다. 취소·변경 여부는 원문 확인이 필요하다. 항목의 마지막 수집 시각과 전체 실행 시각을 구분한다.

## 보관 범위와 변경 절차

여기서 보관은 사이트 JSON·목록·검색을 뜻한다. Git 커밋 이력의 영구 삭제나 원문 콘텐츠 전재를 뜻하지 않는다. 기본 공개 JSON 4종을 유지하며 날짜·제공처·원문 링크·최소 설명만 보관한다.

사용자 결정 변경 시 이 문서와 공통 수명 규칙 코드·수집기·필터·테스트·PLAN·AUTOMATION을 함께 대조한다. 이번 개발은 로컬 구현·검증 범위이며 아직 원격 스케줄·운영 데이터에 반영됐다고 표시하지 않는다.
