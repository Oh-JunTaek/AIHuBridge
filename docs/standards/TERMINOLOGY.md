# AI 허브릿지 용어·표기 가이드

기준일: 2026-10-29. 사용자 화면과 현재 안내 문서의 용어 선정 기준이다. 루트 AGENTS.md의 운영·개발 규칙과 [문서 우선순위](./DOCUMENTATION.md)를 함께 적용한다. 삭제한 ‘용어 사전’ 기능을 복원하는 문서가 아니다.

## 선정 원칙

1. 실제 포함 범위를 이름으로 설명한다. 뉴스·공식 발표·논문을 함께 다루는 상위 공간은 **AI 소식**이다. 기업 SNS가 추가되어도 이 이름을 유지할 수 있다.
2. 주제, 제공처, 제공처 유형, 지역, 자료 언어를 구분한다. 기업 공식 채널의 글이 모두 제품 발표인 것은 아니며 한국어 자료가 모두 국내 출처인 것도 아니다.
3. 화면 제목·메뉴·이동 버튼·접근성 이름·오류 안내·문서에서 같은 대상을 같은 말로 부른다. 일반적인 명사와 짧은 행동 표현을 사용한다.
4. 확인한 사실까지만 표현한다. ‘오픈소스 언급’은 라이선스 검증과 다르고 ‘최근’은 ‘오늘’이나 ‘중요’와 다르다. 공식 채널은 출처의 성격이며 게시물의 확정성·신뢰 등급이 아니다.
5. 원문의 제목·제품명·기관명·인증 명칭은 원형을 보존한다. 일괄 치환으로 외부 자료의 의미를 바꾸지 않는다.

## 메뉴·주소 기준

| 상위 메뉴 | 표준 명칭 | 주소 | 범위 |

학습관·정보관 이름을 클릭하거나 터치하면 각각의 소개 화면으로 이동한다. 마우스를 올리거나 상위 메뉴에 키보드 초점을 두면 하위 메뉴가 열리며 소개 화면에서도 각 항목에 바로 갈 수 있다. 설정 메뉴는 제공하지 않으며 이전 `/settings` 주소는 홈으로 이동한다. 기존 페이지명 ‘학습 경로’는 메뉴·제목·홈 이동 버튼·돌아가기 안내에서 **추천 커리큘럼**으로 통일한다. 본문의 일반 표현 ‘학습 경로’와 공식 자료 원문은 그대로 쓸 수 있다. 추천은 공개된 고정 학습 순서를 뜻하며 개인화 추천이 아니다. Tab으로 링크를 이동하며 Escape로 닫아 상위 메뉴에 초점을 돌린다. 바깥 클릭·메뉴 밖 초점 이동·페이지 이동 시 닫는다.

주소는 실제 사이트에서 `/AIHuBridge/` 아래에 배치된다. 이전 `/research`는 `/updates`로 이동하며 검색 문자열·해시를 보존하고 브라우저 방문 기록을 대체한다. 새로운 내부 링크는 `/updates`만 사용한다. `/path`·`/certs` 등 기존 의미가 맞는 주소를 단순 번역 목적으로 바꾸지 않는다.

## AI 소식

| 대상 | 표준 용어 | 사용 기준 |
|---|---|---|
| 상위 공간 | AI 소식 | ‘AI뉴스’, ‘리서치’ 혼용 금지 |
| 혼합 목록 | 소식 / 자료 | 목록·상태 안내는 소식, 원문·언어·수집 설명은 자료 |
| 언론의 개별 보도 | 기사 / 보도 | 실제 언론 기사만 지칭할 때 허용 |
| 분야 | 모델 소식 / 업계·제품 / 연구·논문 / 정책·규제 / 오픈소스·개발 / 미디어·커뮤니티 | 주제와 제공 방식이 겹치는 탐색 묶음이며 상호 배타적 학술 분류가 아님 |
| 출처 지역 | 전체 출처 / 국내 출처 | 한국·한국어 편집 제공처 기준. 사건의 국가·자료 언어와 구분 |
| 개별 제공자 | 제공처 / 전체 제공처 | OpenAI·긱뉴스·arXiv 등 |
| 제공자 성격 | 출처 유형 | 기업 공식 채널 / 커뮤니티·플랫폼 / 언론·매체 / 논문 저장소 |
| 언어 | 자료 언어 / 전체 언어 / 언어 미확인 | 논문·발표에도 적용하므로 ‘기사 언어’ 사용 금지 |
| 기업 필터 | 기업 언급 | 현재 목록이 기업만 포함하므로 ‘기업·기관’으로 확장 표기하지 않음 |
| 모델 구분 | 모델 유형 | 언어 모델 / 음성·음악 모델 / 이미지 모델 / 영상 모델 / 멀티모달 / 코딩 모델 / 로봇·월드 모델 / 임베딩·검색 모델 / 시계열·예측 모델 / 기타 모델 |
| 공개 관련 조건 | 공개 방식 언급 | 오픈소스 언급 / 가중치 공개 언급 / 비공개 언급 / 미확인·혼합 |
| 논문 구분 | 세부 주제 / 논문 유형 | 원문 분류 코드·제목·초록 키워드 기반. 동료평가·중요도·획기성 판정이 아님 |
| 원문 날짜 | 원문 게시일 | 기존 publishedAt의 날짜. 논문 제출·발표·기사 발행의 원문 날짜를 수집일로 대체하지 않음 |
| 수집 날짜 | 마지막 수집 | 운영 수집 시각. 개별 원문 게시일·브라우저 접속 시각과 다름 |

‘오픈소스·개발’에 포함되었다고 모든 자료나 모델이 오픈소스인 것은 아니다. ‘미디어·커뮤니티’에는 긱뉴스 토론 글도 포함되므로 ‘언론’만으로 표시하지 않는다. ‘논문 저장소’는 제공처 유형으로 한 번 표시하며 ‘논문 원문’ 배지를 중복해서 붙이지 않는다.

## 코드·자료 호환과 변경 절차

- 일반 화면 문구는 `src/lib/i18n.ts`, 모델·주제·출처 유형 문구는 `src/lib/news-facets.mjs`를 먼저 확인한다. 이미 있는 명칭을 임의로 새로 만들지 않는다.
- `news.json`, `News Refresh`, `NewsItem`, `sourceId`, 분야 키(`연구/논문`, `언론`, `오픈소스` 등)는 운영·자료 호환 식별자다. 화면 용어 정리만을 이유로 바꾸지 않는다. 표시 명칭과 내부 키는 다를 수 있다.
- 수집 출처의 공식 이름, 원문 제목, 학습 자료·인증의 고유 명칭, 날짜가 붙은 과거 보고서는 일괄 치환하지 않는다. 현재 안내 문서에서 새 가이드로 연결한다.
- 새 용어가 필요하면 먼저 대상과 포함 범위를 정의하고 기존 용어와 비교한다. 근거 없는 ‘공식·인증·무료·오픈소스·오늘·추천·최고’ 표현을 점검한다. 메뉴·제목·필터·상태·접근성 문구·주소의 일치를 확인한다.
- 주소 변경은 이전 공유 링크의 이동·검색 문자열·해시·뒤로 가기까지 확인한다. GitHub Pages의 SPA 경로는 직접 HTTP 요청이 404일 수 있으므로 실제 브라우저 표시와도 구분한다.
- 기업 SNS는 공식 계정과 관계자 개인 계정을 구분한다. 게시물의 실제 작성자·채널을 표시하며 공지/예고/추측을 서비스가 자동 등급화하거나 그 기준으로 제외하지 않는다. 지원 플랫폼과 계정은 출처 관리표 기준이다.
- 완료 시 현재 문서·작업 결과에 변경 전후와 검증 범위, 남은 제약을 기록한다.
