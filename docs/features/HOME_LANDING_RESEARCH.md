# 홍보 홈 개편 — 레퍼런스 조사와 선택 후보

조사일: 2026-10-29(KST). 상태: **기획 후보 제출 / 사용자 선택 전 / 서비스 코드 미변경**.

## 1. 목적과 화면 구조

처음 들어온 사람이 ‘AI 소식과 배울 거리, 참여할 일정을 한곳에서 찾는 서비스’임을 시각적으로 이해하게 한다. 주 대상은 AI 정보를 찾거나 학습을 시작하려는 한국어 사용자로 가정한다. 긴 기능 설명 대신 짧은 제목, 자체 그래픽, 실제 기능을 단순화한 장면을 사용한다.

사용자 요청으로 확정한 방향은 기존 첫 화면을 **대시보드 항목**으로 이동하고 별도의 **홍보 홈**을 만드는 것이다. 이번 작업은 조사·기획까지만 수행한다.

| 진입 | 현재 코드 | 개편 제안 |
|---|---|---|
| 최초 진입 `/` | 최근 소식 중심 Home | 새 홍보 홈 |
| 브랜드 로고 클릭 | `/` | 새 홍보 홈 `/` |
| 대시보드 메뉴 | 없음 | 독립 상위 항목, `/dashboard` 제안 |
| 학습관·정보관·설정 | 기존 메뉴 | 기존 목적과 하위 주소 유지 |
| 홍보 홈 주 버튼 | 해당 없음 | `대시보드 보기` |

‘아이콘’은 헤더 브랜드 로고로 해석했다. 별도의 설치 앱 아이콘이나 즐겨찾기 주소까지 바꾸는 요청으로 확장하지 않는다. 새 홈을 매번 `/`에서 보여주되, 재방문자를 자동으로 대시보드로 보내는 개인 저장값은 도입하지 않는 안이다.

코드 확인: `src/pages/Home.tsx`는 최근 7일 자료 최대 6건, TodayBrief, 소식 카드 4건과 추가 2건, 로딩·실패·빈 상태를 제공한다. `src/main.tsx`의 인덱스 경로가 Home이며 `/dashboard`는 없다. `SiteNavigation.tsx`는 학습관·정보관·설정으로 구성된다. 대시보드 이동은 기존 동작을 보존하는 작업이며, 새로운 통계·개인화 대시보드 개발을 뜻하지 않는다.

## 2. 조사 범위와 읽는 방법

공식 사이트 12곳에 접근했다. 11곳은 본문 또는 실제 화면을 확인했고 Khan Academy는 본문을 확보하지 못해 평가에서 제외했다. 아래 ‘관찰’은 확인한 구성이고 ‘적용’은 AI 허브릿지를 위한 제안이다. 지역·언어·방문 시점에 따라 화면이 달라질 수 있다.

Linear, Raycast, Notion, Reader, Stripe, Raindrop, Are.na, 토스는 데스크톱 브라우저 첫 화면도 직접 확인했다. Apple·Framer·Feedly는 공식 페이지 본문/이미지 설명 기반 조사다. 정지 화면만으로 원본의 애니메이션 속도·반복 여부를 단정하지 않는다. 이후 제시하는 모션 수치는 모두 우리 서비스용 제안이다.

| 레퍼런스 | 확인한 구성 | 가져올 원리 | 그대로 적용하기 어려운 부분 |
|---|---|---|---|
| [Linear](https://linear.app/) | 어두운 여백, 좌측 대형 제목, 하단 대형 제품 화면. 아래에서 업무 단위로 기능 설명 | 복잡한 UI 중 한 장면을 크게 보여주기 | 작은 글씨가 가득한 업무 도구 화면은 공개 정보 서비스에 무거움 |
| [Raycast](https://www.raycast.com/) | 검정 바탕 중앙 문구, 키보드·확장 도구·기능 시연으로 이어지는 구성 | 중심 오브젝트 하나로 기억 만들기 | 첫 화면에서 기능이 늦게 드러나면 우리 서비스의 정체가 흐려짐 |
| [Notion](https://www.notion.com/) | 밝은 바탕 대형 한국어 제목, 강조 그래픽, 버튼, 제품 화면. 기능을 큰 묶음으로 설명 | 짧은 말과 시각 자료의 조합, 기능 묶음별 설명 | 팀·에이전트·자동화 기능은 우리 서비스에 없음 |
| [Readwise Reader](https://readwise.io/read) | 중앙 제목·버튼 아래 데스크톱/모바일 화면, 다양한 자료를 한곳에 모으는 설명 | 흩어진 정보를 한곳에서 보는 가치를 화면으로 증명 | 저장·하이라이트·동기화 기능까지 차용하면 오해 발생 |
| [Stripe](https://stripe.com/) | 밝은 바탕의 넓은 컬러 그래픽, 큰 제목, 사업별 기능 섹션 | 브랜드 그래픽과 구체적 기능 장면 결합 | 금융 지표·고객 로고·복잡한 영업 동선은 부적합 |
| [Raindrop.io](https://raindrop.io/) | 좌측 제목과 버튼, 우측 크고 잘린 제품 화면, 자료 썸네일과 기능별 이미지 | ‘자료가 모여 있다’를 가장 빨리 보여주는 비대칭 구성 | 북마크·개인 컬렉션 서비스처럼 보이지 않게 구분 필요 |
| [Are.na](https://www.are.na/) | 넓은 흰 여백과 작은 문장, 수집·정리·검색·연결 순서 | 정보 사이의 관계를 설명하는 방식 | 현재 첫 화면은 텍스트 중심이어서 이번 요구와 거리가 있음 |
| [Framer](https://www.framer.com/) | 제품 정의, 시작 버튼, 영상과 고객 사례가 이어지는 구성 | 긴 설명 대신 대표 시연 장면 | 제작 툴처럼 보이는 편집기 UI·프롬프트 입력창은 부적합 |
| [Apple](https://www.apple.com/) | 짧은 제품명·문구·행동 링크와 큰 제품 이미지의 반복 | 한 구간에서 하나만 크게 보여주기 | 실물 제품 대신 소식·달력·학습 그래픽이 필요 |
| [토스](https://toss.im/) | 한국어 메뉴 아래 생활 장면을 크게 사용하는 둥근 메인 비주얼과 짧은 문구 | 친숙한 장면과 큰 한국어 문구의 전달력 | 인물 영상 제작·구매 부담, 금융 브랜드 연상 |
| [Feedly](https://feedly.com/) | 현재 메인은 위협 정보 대상, 수집·분석·전달 과정과 사용 사례 | 자료가 들어와 목적에 맞게 보이는 과정 | 현재 B2B 보안·AI 분석 메시지는 우리 서비스와 다름 |
| [Khan Academy](https://www.khanacademy.org/) | 이번 도구에서 본문 확보 불가 | 평가 보류 | 확인하지 못한 교육 홈 디자인을 근거로 사용하지 않음 |

시사점: 유명 서비스의 색을 복제하기보다 **대표 장면 하나 + 짧은 정체성 문구 + 명확한 진입 버튼**을 가져오는 편이 적합하다. 데이터 목록과 필터를 홈에 다시 쌓으면 새 대시보드와 구별되지 않는다.

## 3. 선택할 수 있는 여섯 방향

각 안의 색·서체는 확정 디자인이 아니라 비교용 출발점이다. 서체는 기존 한글 시스템 산세리프 계열을 우선 활용하며 외부 폰트 도입은 실제 자산·라이선스 검토 후 결정한다. 본문은 읽기 쉬운 굵기, 제목은 굵은 한글 고딕으로 구성한다.

### A. 연결되는 지식의 다리 — 브랜드 중심

- 한 장면: 왼쪽의 소식 조각, 오른쪽의 일정·책·학습 경로가 하나의 선형 다리로 연결된다. HuBridge라는 이름과 연결하는 자체 그래픽이다.
- 제목: **AI 소식에서 배움까지, 하나로 잇다.** 보조 한 줄: `소식·일정·교육 정보를 한곳에서 살펴보세요.`
- 구도: 좌측 제목/버튼 35%, 우측 그래픽 65%. 흰 배경 `#FFFFFF`, 잉크 `#172B4D`, 파랑 `#2357C6`, 하늘 `#DCEBFA`, 기존 브랜드와 이어지는 호박색 `#B86612`.
- 모션: 선이 1.2초 동안 한 번 연결되고 네 종류의 자료가 제자리에 놓인다. 이후 정지. 장식용 입자·무한 궤도 회전은 쓰지 않는다.
- 아래 구간: 다리가 연결한 네 기능 확대 → 한눈에 보는 대시보드 장면 → 진입 버튼.
- 모바일: 제목 아래 세로로 짧은 연결 그래픽. 가로 이동이나 스크롤 고정 없이 읽는다.
- 참고: [Stripe](https://stripe.com/)의 브랜드 그래픽 비중 + [Notion](https://www.notion.com/)의 짧은 기능 설명 원리. 다리 형태는 자체 제안.
- 장점: 이름과 화면이 연결되어 기억하기 쉽다. 유의점: 추상적인 다리만 그리면 무엇을 제공하는지 알기 어려워 네 기능의 명칭과 형태가 필요하다.
- 난도: 중간. 자체 SVG 메인 그래픽 1개, 기능 그래픽 4개.

```text
로고             대시보드  학습관  정보관  설정
AI 소식에서       소식 ───╮      ╭── 일정
배움까지,        자료 ────╰─ 다리 ─╯── 배움
하나로 잇다.              교육·인증
[대시보드 보기]
```

### B. 움직이는 서비스 쇼케이스 — 이해도 중심

- 한 장면: AI 소식 카드, 달력의 일정 점, 4단계 학습 경로를 크기가 다른 세 화면으로 배치한다. 실제 기능을 단순화한 그림이며 조작 가능한 필터처럼 보이지 않게 한다.
- 제목: **AI 소식, 일정, 배울 곳을 한눈에.**
- 구도: 제목은 좌측, 우측은 큰 소식 화면에 작은 달력·학습 화면을 겹친다. 배경 `#F7FAFC`, 글자 `#182330`, 흰색 `#FFFFFF`, 파랑 `#245DCC`, 청록 `#277C78`.
- 모션: 첫 진입 때 세 화면이 12px 이내에서 자리 잡는 0.8초 연출. 이후 사용자가 기능명을 선택하면 해당 그림만 바뀐다. 자동 슬라이드 금지.
- 아래 구간: `소식을 살펴보고` / `일정을 찾아보고` / `배움을 시작하고`를 큰 그래픽 세 장으로 소개. 교육·인증은 학습 장면 안에서 별도 명칭으로 구분.
- 모바일: 첫 화면에는 대표 그림 하나만 보이고 나머지는 아래에서 보인다. 축소한 데스크톱 스크린샷을 억지로 넣지 않는다.
- 참고: [Raindrop.io](https://raindrop.io/), [Reader](https://readwise.io/read), [Linear](https://linear.app/).
- 장점: 실제 제공 기능이 즉시 전달된다. 유의점: 너무 많은 실제 기사 문구를 넣으면 대시보드처럼 보이므로 그림의 정보량을 줄여야 한다.
- 난도: 낮음~중간. 자체 UI 일러스트 3종. 날짜·숫자는 실제 최신 자료로 오인할 수 없게 예시임을 표시하거나 생략.

```text
AI 소식, 일정,           ┌──── AI 소식 ────┐
배울 곳을 한눈에.        │ 자료 형태 그림  │
                        └───────────────┘
[대시보드 보기]      [달력 그래픽] [학습 경로]
```

### C. AI 탐색 지도 — 둘러보는 경험 중심

- 한 장면: AI 허브릿지를 중심으로 소식·일정·커리큘럼·교육 및 인증의 네 목적지가 연결된 평면 지도.
- 제목: **넓은 AI 세계, 여기서부터.** 보조: `소식부터 학습과 행사까지 살펴보세요.`
- 구도: 중앙 제목 아래 가로로 넓은 지도. 바탕 `#F4F8F6`, 글자 `#20392E`, 초록 `#33775B`, 파랑 `#4267A0`, 노랑 `#E5C864`.
- 모션: 첫 진입 시 경로를 한 번 그린다. 목적지에 포커스하거나 마우스를 올리면 해당 연결선만 강조한다.
- 아래 구간: 네 목적지의 그림 설명 → 대시보드 진입. 지도에서 바로 각 기존 페이지로 이동하는 것은 선택 가능한 상세안.
- 모바일: 복잡한 지도를 네 목적지의 세로 경로로 재배치. 줌·드래그를 요구하지 않는다.
- 참고: [Are.na](https://www.are.na/)의 연결 개념과 [Feedly](https://feedly.com/)의 과정 설명에서 착안. 지도 자체는 원본에 대한 관찰이 아니라 신규 제안.
- 장점: 서비스가 여러 분야를 연결한다는 점을 보여준다. 유의점: 가벼운 홍보 홈보다 탐색 도구처럼 느껴질 수 있다.
- 난도: 중간~높음. 데스크톱·모바일 별도 지도 구도와 키보드 이동 설계.

```text
           넓은 AI 세계, 여기서부터.
       소식 ───── AI 허브릿지 ───── 일정
                    │
         추천 커리큘럼 ─── 교육·인증
               [대시보드 보기]
```

### D. AI 정보 매거진 표지 — 차분한 시각 자료 중심

- 한 장면: 책·달력·자료 페이지의 자체 도형 일러스트를 비대칭으로 편집한 큰 표지. 기사 목록을 가져오지는 않는다.
- 제목: **AI를 읽고, 배우고, 만나는 곳.**
- 구도: 큰 제목과 세로형 그림이 교차한다. 바탕 `#FAFAF7`, 글자 `#292D31`, 파랑 `#34538C`, 밝은 회색 `#E3E7EA`, 호박색 `#AE681C`. 제목은 굵은 고딕, 작은 캡션은 보통 굵기.
- 모션: 표지 속 달력 한 장이 살짝 정렬되는 0.6초 동작 1회. 글자 흘러가기와 자동 기사 전환 없음.
- 아래 구간: 소식·학습·일정의 세 큰 편집면 → 서비스 진입.
- 모바일: 하나의 긴 포스터처럼 세로 편집. 장식 이미지보다 기능명이 먼저 읽힌다.
- 참고: [Apple](https://www.apple.com/)의 큰 이미지와 짧은 문구 반복, [Raindrop.io](https://raindrop.io/)의 시각 자료 배치 원리.
- 장점: 편안하고 정보 서비스라는 인상이 뚜렷하다. 유의점: 독창적인 그림이 부족하면 평범한 블로그 홈처럼 보인다.
- 난도: 중간. 자체 편집용 일러스트 3~4종.

```text
AI를 읽고,       ┌── 큰 표지 그림 ──┐
```

### E. 디지털 전시관 — 강한 첫인상 중심

- 한 장면: 깊은 남색 바탕에 종이·달력·학습 경로를 상징하는 큰 오브젝트 하나를 전시한다. AI 로봇이나 뇌 대신 실제 서비스의 자료 형태를 쓴다.
- 제목: **AI의 흐름을 만나는 입구.** 보조: `소식·일정·학습 정보를 둘러보세요.`
- 구도: 중앙 오브젝트를 넓게, 제목과 버튼은 바로 읽히는 위치에. 남색 `#132645`, 흰색 `#F4F7FC`, 밝은 파랑 `#80A9EC`, 회청색 `#637997`, 호박색 `#DFA64D`.
- 모션: 오브젝트가 1초간 펼쳐지며 소식·일정·학습의 세 면을 보여주고 멈춘다. WebGL·동영상 없이 SVG/CSS로 시작하는 안.
- 아래 구간: 밝은 배경으로 전환해 네 기능을 큰 그림으로 설명 → 진입 버튼.
- 모바일: 오브젝트는 정적 포스터로 대체해도 메시지가 유지되게 설계.
- 참고: [Raycast](https://www.raycast.com/)의 절제된 첫 화면, [Reader](https://readwise.io/read)의 어두운 히어로, [토스](https://toss.im/)의 큰 메인 비주얼.
- 장점: 홍보 간판의 인상은 강하다. 유의점: 기능 설명보다 분위기가 앞설 위험이 있고 자산 제작 부담이 가장 크다.
- 난도: 높음. 라이트·다크 환경에 어울리는 독자적 오브젝트와 정적 대체 이미지 필요.

```text
             AI의 흐름을 만나는 입구.
                 [큰 전시 오브젝트]

                  [대시보드 보기]
```

### F. 네 가지 창 — 가장 간결한 안내형

- 한 장면: AI 소식·AI 캘린더·추천 커리큘럼·교육 및 인증을 서로 다른 모양의 그림으로 보여주는 큰 네 창. 같은 카드 네 장의 반복보다 폭·내부 구도를 다르게 만든다.
- 제목: **AI 정보 탐색, 여기서 시작하세요.**
- 구도: 짧은 중앙 제목 아래 2×2 그림, 하단 주 버튼. 흰색 `#FFFFFF`, 글자 `#26323D`, 청록 `#247C85`, 하늘 `#DBEEF2`, 노랑 `#E8BD64`.
- 모션: 진입 시 네 창이 함께 한 번 나타난다. 호버/키보드 포커스 때 선택한 창 안의 선만 움직인다.
- 아래 구간: 필요한 경우 한 줄 서비스 설명과 푸터로 끝낸다. 긴 스크롤을 요구하지 않는다.
- 모바일: 2열을 유지할 수 없으면 1열로 배치하며 그림 안 글자를 축소하지 않는다.
- 참고: [Notion](https://www.notion.com/)의 기능 묶음별 설명, [Apple](https://www.apple.com/)의 독립된 제품 단위 구성.
- 장점: 빠르게 이해하고 원하는 곳으로 갈 수 있다. 유의점: A·E보다 브랜드의 독특한 인상이 약하다.
- 난도: 낮음. 기능별 자체 SVG 4종.

```text
       AI 정보 탐색, 여기서 시작하세요.
       ┌── 소식 그림 ──┬── 달력 그림 ──┐
```

## 4. 후보 비교와 추천

아래 평가는 실제 사용자 실험 결과가 아니라 이번 요구에 대한 기획 판단이다.

| 후보 | 기억에 남는 인상 | 기능 이해 | ‘살짝’ 움직임과의 적합성 | 제작 부담 | 선택 이유 |
|---|---|---|---|---|---|
| A 지식의 다리 | 높음 | 높음 | 높음 | 중간 | 브랜드 고유의 간판을 원할 때 |
| B 서비스 쇼케이스 | 중간~높음 | 매우 높음 | 높음 | 낮음~중간 | 무엇을 하는 서비스인지 빨리 알리고 싶을 때 |
| C 탐색 지도 | 높음 | 중간~높음 | 중간 | 중간~높음 | 둘러보는 재미가 중요할 때 |
| D 매거진 표지 | 중간~높음 | 높음 | 매우 높음 | 중간 | 차분하고 세련된 정보 서비스 인상을 원할 때 |
| E 디지털 전시관 | 매우 높음 | 중간 | 중간 | 높음 | 강한 첫인상에 투자할 때 |
| F 네 가지 창 | 중간 | 매우 높음 | 매우 높음 | 낮음 | 짧고 명료한 홈이 필요할 때 |

**우선 비교 추천: A / B / D.** ‘간판’이라는 목적에는 A, 전달력에는 B, 절제된 시각 구성에는 D가 잘 맞는다. 하나로 섞기 전에 1~2개를 고르는 편이 방향이 선명하다. 조합한다면 A의 첫 장면 아래 B의 단순화된 기능 장면을 붙이는 안이 유력하다. 선택 전 확정하지 않는다.

## 5. 모든 후보의 공통 기준

- 첫 화면의 시각 자료 비중은 대략 60~70%를 목표로 한다. 제목 한 줄 또는 두 줄, 설명 한 줄, `대시보드 보기` 버튼을 기본으로 하고 긴 문단은 제외한다. 기능명·버튼·대체 텍스트는 이해와 접근성을 위해 유지한다.
- 홈은 소개용 장면, 대시보드는 실제 최신 소식. 가짜 기사·가짜 행사·성과 수치·고객 로고·개인 진도·추천 정확도 등을 홍보 근거로 넣지 않는다.
- ‘AI가 요약’, ‘실시간 수집’, ‘개인 맞춤’, ‘모든 강의 무료’ 같은 현재 범위 밖 주장은 하지 않는다. 교육 정보 탐색과 자체 강의 제공을 구분한다.
- 핵심 그림은 직접 제작한 SVG나 허용된 자산으로 구성한다. 레퍼런스의 이미지·영상·화면을 그대로 서비스에 배포하지 않는다.
- 첫 화면은 애니메이션 완료 전에도 제목과 버튼이 보인다. 자동 모션은 1회, 1.5초 안팎 이하를 목표로 한다. 연속 부유·점멸·패럴랙스·스크롤 가로채기는 제외한다.
- 움직임 줄이기 설정에서는 정적 최종 상태를 표시한다. 키보드 포커스, 터치, 라이트·다크, 작은 화면에서도 핵심 설명을 유지한다.
- 자산 비용을 줄이기 위해 동영상·3D 엔진보다 SVG/CSS를 우선 검토한다. 이는 성능 측정 결과가 아니라 구현 방침 제안이다.
